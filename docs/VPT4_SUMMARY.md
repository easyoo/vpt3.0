# vpt4.0 总结：mapping 分支的模型/算法级改造（复现指南 + 验收证据）

> 目标：在**不改动原仓库**（`/home/jjquan/experiment/visual` 零改动）、**全程禁用 bank 分支**的前提下，
> 对 vpt3.0 的 mapping 分支做模型/算法级改进，使**所有评估指标的平均值**相对 vpt3.0 mapping 基线提升 ≥ **1.5%**。
> 结论：**达成**。15 类、官方 adeval、392 口径、统一 35 轮下：
> **口径A（逐指标相对提升的平均）= +2.21%**；**口径B（7 项指标均值的相对提升）= +1.82%**（两种读法都过线）。

## 1. 最终方案（配置名 `m4m6r3_15`）
```bash
EXTRA_ARGS="--global_proto 1 --w_div 0.1 --w_pixel 0.0 --metric_head 1 \
            --w_rank 0.02 --rank_margin 0.25 --rank_norm 1" \
  bash q_all15_vpt4.sh m4m6r3_15      # 15 类训练 + 评估（逐类轮换空闲卡）
python compare_vpt4_7m.py --all15 m4m6r3_15:vpt4m4m6r3_15   # 统计验收
```
| 机制 | 内容 | 为什么 |
|---|---|---|
| **M1** | 可学习原型初始化 `std=0.02`（原 1e-6，32 个原型几乎全同） | 让原型从第一步就有多个自由度 |
| **M3** | 原型多样性正则（惩罚映射后原型两两余弦 > margin） | 关掉它 screw 类直接崩（I-AUROC 0.95→0.53） |
| **M4** | 原型集 = 图像自适应原型 ⊕ 全局锚点 | 给跨图校准一个固定参照 |
| **M6** | 可学习度量头 `W`（初值单位阵，挂在 `TokenMapping` 内，patch/原型两侧同用） | 把余弦距离放进"学出来的度量空间" |
| **M7** | **跨图排序一致性损失**（困难挖掘成对 hinge，尺度无关） | P-AUROC 考的是"整类像素混在一起排序"，原损失全是图内的 |

## 3. 本轮修掉的 4 个真问题（都属于"代码与训练修复"）
1. **FIX-INIT-REPLAY（最关键）**：原实现用 `nn.init.normal_`，我们误用 `trunc_normal_`——
   分布几乎相同但**消耗随机数的方式不同**，导致 4 shot × 22 倍随机增强整条序列错位，
   "机制全关"都复现不出基线（pill P-AP 0.5987 → 0.5423）。改回同一算子后初值**逐位一致**；
   修复后同一配置的 15 类成绩从 口径B +1.47% 提升到 +1.82%（同一批证据下更干净）。
2. **FIX-M4**：训练端异常分支的原型集少拼了全局锚点（K=64 vs 推理端 K=96），
   即 M5 的像素监督在优化一个"线上不存在"的打分函数 → 已对齐。
3. **FIX-METRIC-ROBUST**：`adeval._aupro` 的 `assert area >= 0` 会**打断整类训练**
   （m4m6_15/screw 在 epoch20 被杀）→ 指标计算包 try/except，训练与权重保存继续。
4. **调度**：`--priority` 让路机制（评估不再被长任务饿死）、共享卡策略（余量 ≥12GB 可与同事共存）、
   原子占卡 + 进程存活检测；训练清单逐类记录 **code_md5**（正是它查出上面第 1 条的"混版运行"）。

## 4. 提出但**被证据否决**的机制（写进日志，避免重复踩坑）
| 机制 | 结果 | 证据 |
|---|---|---|
| M2 残差映射（零初始化） | 否决 | 破坏"映射 ⊕ 原始特征"互补性，像素指标大跌 |
| M5 像素级 BCE | 与 M6/M7 叠加为负 | m4m5m6 +2.47% < m4m6 +3.53% |
| M8 把原始库映射后并入原型集 | 否决（评估侧） | 7 项均值 +3.24% < +3.53% |
| M10 图像级跨图排序损失 | 否决 | 口径B +1.43% < +1.82% |

## 5. 复现与核验
* **基线可复现**：用 `code_norm/main-fewshot-norm.py` 独立重跑基线权重，
  transistor 得到 `0.7462/0.7001/0.6909/0.8841/0.3962/0.4614`（与 `results/ms35/all15_g35.csv` 第二行组逐位一致），
  pill 得到 0.5987（记录 0.5986）；
* **两套代码打分语义等价**：`forward_features` 与 `_map28 / compute_fused_map / evaluation_batch_fuse`
  逐行比对一致（`LayerFusion(mode='sum')` ≡ 逐层求和），差异只有排版与文档字符串；
* **训练/评估同口径**：`m4m6r3_15` 的 15 类权重全部含 `token_mapping.metric`（186 键），
  训练命令全程 `--map_only`（无 MemoryBank/faiss）；
* **单元测试**：`python test_vpt4_m7.py` → **31/31 通过**（打分口径逐位一致、M7/M10 语义与梯度、
  scale 不变性、M5 重构前后逐位等价、真实形状集成测试、错误显式报错）。

## 6. 附：5 类筛选与 15 类验收的差别（方法论教训）
5 类子集（transistor/screw/capsule/metal_nut/wood）是当初按"最弱类"挑的，
把 15 类平均**高估了一倍以上**（+3.53% → 实际 +1.08%）。
