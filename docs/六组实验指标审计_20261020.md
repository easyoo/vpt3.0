## 总体结论

六组表的算术链路基本正确：样本重排、双分支融合、Gaussian、top-0.5% 图像分数、AUROC/AP/F1/PRO 调用与缓存形状均能对上，代表类别独立复算的最大绝对误差约 `2.38e-5`。

但当前指标不能全部视为严格、纯归纳式的少样本结果：

1. `MVTec 4-shot` 的 60 张合成源图中只有 5 张属于当前可追溯的 4-shot 清单，另外 55 张来自其他正常训练图。该实验不是严格 4-shot，`89.4721` 应停止作为正式 4-shot 结果引用。
2. 双分支融合的 z-score 使用了整个类别全部测试图的像素统计量，属于转导式融合。不过完全取消归一化后，六组七项均值只下降约 `0.05–0.43` 个点；此前用“逐图 z”作为对照，夸大了该归一化的实际贡献。
3. AUPRO 当前实现使用 `nstrips=200`，常用参考实现使用 100 个阈值；代表类别上当前值比标准 100 阈值高约 `0.66–0.84` 个点。
4. 图像分数取 top-0.5% 和融合规则均不是完全预先固定的独立验证选择；top-1% 使六组 I-AUROC 下降约 `0.77–1.15` 个点。

结论：

- **MVTec 1-shot、VisA 1/2/4-shot**：在明确标注“类内测试集 z-score、top-0.5%、单 seed”的前提下，数值可复现；完全 raw 版本比正式表低 `0.11–0.43` 个七项均值点，可作为 inductive 保守口径。
- **MVTec 2-shot**：计算链路正确、合成源与 2-shot 清单一致；raw 版本为 `88.0219`，比正式表低 `0.3112`，仍受单 seed 限制。
- **MVTec 4-shot**：不是严格 4-shot，当前 `89.4721` 不可公平引用。

## 逐项审计

### 1. 数据与泄漏

#### 🟢 训练集与测试集隔离

证据：

- 六组训练命令均带 `--map_only`，训练期未构建或读取 MVTec/VisA 测试集的 bank error map。
- 映射模型训练只使用 `train/good` 的 shot，以及对应正常 shot 生成的合成异常。
- 合成图片和目标 mask 与测试图片、测试 GT 的精确文件哈希重叠均为 0。
- 测试标签只进入指标函数，未进入训练损失或融合选择。

验证方法：

- 已检查训练日志命令、`AnoStylerGeneratedDataset`、mapping bank 构建和 eval DataLoader。
- 已对六组输入图、合成图、mask、测试图做文件级 SHA-256 检查。

判定：没有发现测试图片或测试标签直接进入训练。

#### 🔴 MVTec 4-shot 不足 4 张正常图的信息预算

证据：

- 当前可追溯的 4-shot 清单与旧 AnoStyler 配置的合成源图只在 60 个位置中重合 5 个。
- `carpet`：4/4 重合。
- `cable`：1/4 重合。
- 其余 13 类：0/4 重合。
- 例如 `bottle`：
  - 训练 shot：`034, 145, 195, 205`
  - 合成源图：`000, 068, 114, 178`

这意味着模型在 MVTec 4-shot 中实际看到了最多 8 张不同正常图的信息，部分类别甚至完全没有使用清单中的 4 张 shot 来合成训练异常。虽然这些图仍来自正常训练集、不是测试集泄漏，但属于严重的 few-shot 信息预算泄漏，不能称为严格 4-shot。

验证方法：

1. 使用与 `.shots/<class>_shot4_seed1.json` 完全相同的 4 张正常图重新运行 AnoStyler。
2. 从同一代码版本、同一 seed 重新训练 35 epochs。
3. 重新生成 mapping 和 bank 异常图并重算指标。

修复建议：在严格 4-shot 结果出来前，将该行标记为 `non-strict 4-shot, extra normal images`，不要与 SUBAD 等论文的 4-shot 表直接比较。

#### 🟡 MVTec 4-shot 训练源码不可闭环

证据：

- MVTec 4-shot 训练日志记录的代码 MD5 为 `81741839698c`。

  - `08d8528b4a59`：vpt3.5/vpt3.6
  - `6a9d0c5b778e`：vpt3.7
  - `d4fad7eb14ff`：当前审计代码

验证方法：恢复 `81741839698c` 对应源码，或检查实验时 `/home/jjquan/datasets/mvtec` 的真实内容与当前 `/home/jjquan/MVTec-AD` 的文件哈希是否逐项一致。

#### 🟡 VisA 4-shot 的合成 prompt 与 1/2-shot 不一致

证据：

修复建议：正式表使用一致的 prompt 模板，或明确将该差异作为因子做单独消融。

### 4. 转导式类内归一化

#### 🟡 当前融合依赖同类别全部测试图的统计量，但实际影响有限

代码位置：`sweep_fusion_advanced.py:32-33`

```python
def z(x):
    return (x - x.mean()) / (x.std() + 1e-8)
```

这里的均值和方差来自整类全部测试像素。单张图的分数会随同批其他测试图变化，因此该方法不是逐样本独立推理。

### 8. 异常合成器来源

AnoStyler 当前仓库没有同任务数据集上额外训练的 U-Net checkpoint。其生成过程使用 SAM、CLIP 和 VGG 预训练模型，对每个正常 shot 做逐图风格优化。未发现 AnoStyler 在 MVTec/VisA 异常训练集上预训练的本地证据。

但仍有盲区：CLIP/VGG/SAM 的公开预训练语料是否包含目标数据集图片无法从本地材料证明。这是所有使用公开预训练模型的少样本方法共有问题，不应单独针对本方法，但论文应声明预训练来源。

## 最关键的五个质疑

1. **MVTec 4-shot 是否真的是 4-shot？**  
   目前可以明确反驳：不是。55/60 张合成源图不在 4-shot 清单中。

2. **双分支融合是否使用测试集统计量？**  
   是。整类测试像素参与 z-score，指标依赖同批其他测试图；但完全 raw 后七项均值只降约 0.05–0.43 个点。

3. **top-0.5%、box25、融合权重是否在测试集上选过？**  
   目前只能判定“存疑”。需要参数选择日志或独立 calibration split 才能排除。

4. **AUPRO 是否能与论文直接比较？**  
   不能直接比较。当前 `nstrips=200`，标准参考通常为 100，代表类别差约 0.66–0.84 个点。

5. **单 seed 的领先是否稳定？**  
   信息不足。需要三种子完整重训，类别 bootstrap 无法替代训练随机性。
