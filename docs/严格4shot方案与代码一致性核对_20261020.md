# 严格 MVTec 4-shot 当前方案：代码一致性核对

日期：2026-10-20  
审计范围：上一版算法流程说明与 `code_vpt4/main-fewshot-vpt4.py`、`eval_score_v3.py`、`cache_bank_nocrop.py`、`sweep_fusion_advanced.py` 的实际行为。

## 总体结论

上一版方案主体与代码一致，但有三处需要修正或补充：

1. 训练几何实际为 `Resize(448) → CenterCrop(392)`，不是直接用 448 训练。
2. mapping 推理为 `Resize(448)` 不裁剪，再放大 1.5 倍到 672；训练与推理存在明显几何差异。
3. “每类 140 对合成异常都参与训练”不准确；训练器按 defect 目录做 `samples_per_anomaly_type=35` 抽样。

另有一个工程问题已修复：

- `cache_bank_nocrop.py` 的 22 倍增强此前未固定随机种子，已加入 `mod.setup_seed(args.seed)`。

## 1. 数据

### 已确认正确

- 使用已有 AnoStyler 原始 4-shot 数据，未使用 1/2-shot 数据。
- 每类严格 4 个 source image，共 60 个 source。
- 每个 source 有 35 对异常图/mask，共 2100 对。
- strict dataset view 中每类 `train/good` 只有对应 4 张正常图。
- 4 张正常图与 MVTec 原训练图逐字节一致。
- 训练正常图与测试图精确哈希重叠为 0。

### 需要修正的表述

AnoStyler 库存是每类 140 对，但训练 DataLoader 并不保证使用全部 140 对。

```python
AnoStylerGeneratedDataset(..., samples_per_anomaly_type=35)
```

因此实际异常训练数量由 defect 目录数决定：

```text
训练对数 = 35 × defect 目录数
```

当前已有日志显示：

- bottle/cable/capsule/carpet/grid/pill/screw/tile：70；
- hazelnut/transistor/wood：105；
- toothbrush：35。

这是严格的“最多 4 个正常 source”设置，但不是“每个 source 恰好 35 张全部参与训练”。

## 2. 训练几何

### 修正

训练侧实际变换为：

```text
Resize(448,448)
→ ToTensor
→ CenterCrop(392)
→ ImageNet Normalize
```

位置：`main-fewshot-vpt4.py:141-153, 1678`。

正常 shot 和 AnoStyler 异常图都使用该几何。

GT mask 下采样到 patch 网格时使用 `adaptive_max_pool2d`，不是普通平均池化：

```python
resize_mask(mask, num_tokens=H_patch*W_patch)
```

位置：`main-fewshot-vpt4.py:1095-1114`。

因此不能简单说“训练分辨率是 448”；模型实际看到的中心区域是 392。

## 3. 主干与特征融合

### 正确

- 主干：DINOv2 ViT-B/14 with registers；
- 主干参数冻结；
- patch 特征层为 `[1,2,3,4,6,8,11]`；
- 当前实现为直接逐元素相加，没有逐层 L2 或 LayerNorm；
- 深层 layer 11 的范数远大于浅层，实际接近深层主导。

需要明确：

```text
名义上使用 7 层，但数值上并非等权使用 7 层。
```

## 4. 可学习原型与映射

### 正确

- 可学习参数为 32 个 layer-0 token，初始化 std=`0.02`；
- `res_mapping=0`，没有残差映射；
- `metric_head=1`，映射后乘一个初始化为单位阵的 768×768 可学习度量矩阵；
- 映射结构为 `LayerNorm → 768→128 → GELU → LayerNorm → 128→768 → metric`。

### 更正“96 个原型”的性质

推理时的 96 个原型不是 96 个完全固定、与测试图无关的全局参数。

实际为：

```text
layer-0 同一组 32 个 token 被追加两次
→ ViT block 后产生 64 个图像条件 token

再加 32 个全局 token
→ 96 个“图像自适应 token + 全局锚点”
```

训练端与推理端都保留这个重复行为，因此代码一致，但方案描述应称为：

> 64 个图像条件层 token + 32 个全局原型锚点。

不能简单称为 96 个固定 learnable prototypes。

## 5. 训练损失

### 与代码一致

当前严格实验实际启用：

```text
L = 0.5·L_scaled_cos
  + 1.0·L_mse
  + 1.0·L_push_top10
  + 0.1·L_div
  + 0.02·L_rank
  + 1.0·L_seg
```

- `L_scaled_cos`：cosine distance 按 batch 平均距离归一后三次方加权，比例上限 clamp=5；
- `L_mse`：softmax 混合原型与正常 patch 的 MSE；
- `L_push_top10`：异常 patch 到正常 prototype 的 top-10 平均相似度，margin=0.5；
- `L_div`：原型两两余弦超过 0.5 的部分；
- `L_rank`：正常/异常难像素对 hinge，margin=0.25，按正常分数 p75−p25 归一；
- `L_seg`：分割头 Focal + Dice，权重各 0.5。

其余 cluster/distill/EMA/pixel/peak/prod 等默认均为 0。

### 需补充

- 分割损失中的 `pred_score_map` 是 `segmentation_head(mapped patch)`；
- 分割头只在训练中起作用，推理异常图不包含分割头输出；
- 温度 `0.07` 虽被包装为 Parameter，但未加入 optimizer，实际固定为 0.07。

## 6. 训练采样与优化

### 正确

- 每类独立训练；
- 35 epochs；
- seed=1；
- optimizer StableAdamW；
- lr=`1e-3 → 5e-5` cosine schedule；
- warmup 100 iterations；
- weight decay=`1e-3`；
- grad clip=`0.5`。

### 需补充

- 正常增强库每类 88 个视图；
- 每个 iteration 正常分支 batch=`16//2=8`；
- 异常分支 batch=16；
- drop_last=True；
- 因异常样本数可能只有 35/70/105，每个 epoch 的异常 iteration 数为 2/4/6；
- 96 个可学习 token 组中，layer-0 重复 token 也参与了 `L_div`，会形成固定重复对。

## 7. mapping 推理几何

### 关键补充

最终映射推理为：

```text
Resize(448) 无裁剪
→ 1.5× bilinear
→ 实际模型输入 672
→ 单视图、无翻转
```

因此存在明确的训练/推理几何差：

```text
训练：448 resize → center crop 392 → 28×28 patch
推理：448 resize → 1.5× → 672 → 48×48 patch
```

这是当前真实方案的一部分，不能省略。结果讨论时必须说明，否则会误以为训练和测试都在 392 或都在 448。

## 8. mapping raw 分数

### 正确

- raw reference bank 由同样 4 张 shot 在 448（无裁剪）提取；
- bank patch 数为 `4×32×32=4096`；
- 测试 query 为 672，patch 数为 `48×48=2304`；
- raw bank 与 query 存在 448-vs-672 尺度差；
- `d1` 为到全库最近 patch 距离；
- `q512` 为固定 seed 下 1024 个 bank patch 距离的第 512 小值；
- `s_raw=sqrt(d1·q512)`；
- 没有对 bank 做增强，也没有使用测试集统计量。

### 注意

命名中的 “q512” 是 1024 子采样的中位距离，不是测试集分位数，也不是类别级统计量。

## 9. mapping learnable 分数

### 正确

- 使用 `pl=token_mapping(test patch)`；
- 使用 `ql=token_mapping(64 image-conditioned tokens ⊕ 32 global anchors)`；
- `s_learn=min_k(1-cos(pl,ql_k))`；
- `l_global=0`，没有可学习侧全局分位项；
- 最终 mapping map：

```text
mapping_score = 0.6·s_learn + 0.4·s_raw
```

然后插值回 448 保存。

## 10. MemoryBank 分支

### 正确

- 主干：`facebook/dinov2-base`；
- 同样只使用严格 4-shot；
- 每张 shot 22 个增强视图，共 88 张；
- 两组层特征：`[2,3,4,5]`、`[6,7,8,9]`；
- 每组内特征直接求和；
- 特征逐 patch L2 归一化；
- 两个 FAISS inner-product 库；
- 测试 Resize 672；
- 两组最近邻 cosine distance 取平均。

### 已修复

原先 bank augmentation 未设置 seed。现已在 `cache_bank_nocrop.py` 中调用：

```python
mod.setup_seed(int(args.seed))
```

以保证相同 shot、相同 seed 重建出的 22× 增强库一致。

## 11. 最终融合

### 正确

当前严格实验不再使用类内测试集 z-score：

```text
mapping_448 → bilinear 672
bank_672 保持

F = 0.5·box25(mapping_672) + 0.5·box25(bank_672)
→ Gaussian(k=5, sigma=4)
→ top-0.5% 像素均值
```

需要补充：

- `box25` 在 672 上的物理覆盖范围小于旧 448 口径；
- `top-0.5%` 对应像素数量由 `448²×0.5%≈1003` 改为 `672²×0.5%≈2258`；
- GT 在融合脚本中先 bilinear Resize 到 672，再用 `>0.5` 二值化，不是直接 nearest resize。

## 12. 尚未解决的科学风险

方案和代码一致，不等于这些设计都理想。当前仍需注意：

1. 训练 392、推理 672，存在尺度/几何错配；
2. 7 层直接相加实际上深层主导；
3. 96 个原型包含 32 个重复 token；
4. 合成异常库存虽基于 4 个 source，但训练按 defect 类型抽样，各 source 的实际使用次数不均衡；
5. top-0.5%、box25、Gaussian 参数不是独立验证集选出的；
6. 当前为单 seed，尚未证明方差；
7. AUPRO 使用 `nstrips=200`，与 SubAD 的 300 阈值为不同实现。

## 结论

重新核对后的结论是：

- 方案的骨架、模块和公式与代码基本一致；
- 上一版说明遗漏了训练 CenterCrop(392) 与推理 672 的关键差异；
- “140 对全部参与训练”和“96 个固定原型”两处表述需要修正；
- bank 增强随机种子问题已修复；
- 当前严格 4-shot 设置可以继续跑，但论文中必须完整披露上述训练/推理几何与采样细节。
