# `geom` 打分的推广性分析：三个打分点能否统一

> 日期：2026-10-13 ｜ 只推理（`probe_dbar.py` / `probe_dbar_bank.py`，均新增，不训练）
> 权重：VisA 4-shot `vpt35_visa4shot`

## 0. 结论先行

三处**都能改**（同一行公式），但只有两处有意义：

| 位置 | 参考集 | M（4-shot） | 改 geom 是否有意义 | 理由 |
|---|---|---|---|---|
| ① mapping · 可学习原型侧 | 32 图像自适应原型 + 32 全局锚点 | 64 | ❌ **数学上退化** | `d̄` 几乎是常数（≈1.02，波动 ±1%）→ geom 成了 `min` 的单调变换 |
| ② mapping · 原始特征库侧 | K 张 shot 的全部 patch | 4096 | ✅ **已验证有效** | VisA 融合 +0.79 / 裸分支 +2.73 |
| ③ bank 分支 | K×22 增强图的双 stage patch | 90112 / stage | ✅ **最值得做**（未验证） | 库最密 → `d̄` 的全局项权重最高（0.35~0.50） |

## 1. 判据：geom 在对数空间是加权和

```
log √(d_min · d̄) = 0.5·log d_min + 0.5·log d̄
```

所以**全局项在打分里真正的权重** = `std(log d̄) / std(log d_min)`（跨 patch 的变异比）：

* ≈ 0 → `d̄` 是常数 → geom 只是 `min` 的单调变换 → **排序类指标完全不变**（AUROC/AP/F1 一模一样）；
* ≈ 0.1~0.4 → 全局项是真信息，且不喧宾夺主；
* > 1 → 全局项主导，可能丢定位精度。

## 3. 为什么 ① 会退化（本次最有价值的发现）

可学习原型的 `d̄ ≈ 1.02`，即**任意 patch 与几乎所有原型的余弦相似度都≈0**，而 `d_min` 只有 0.006~0.018。
也就是说：这 64 个原型每一个都"极尖锐"，只对某一小簇 patch 有响应，对其它所有 patch 都近似正交。
于是 `d̄` 变成一个几乎恒定的常数（波动只有 ±1%），乘进 geom 里等于乘一个常数。

**这解释了一个此前没想通的现象**：第一轮扫描里，capsules 上 `learn_kn2 / kn3 / kn5 / har3 / minmean / geom`
的输出**到小数点后 4 位完全相同**。当时以为是 bug，现在清楚了——参考集高度冗余时，
各种"多原型聚合"都会退化成同一个排序。

**还有一个更根本的障碍**：可学习侧是**被 `min` 训练出来的**。
训练损失（`L_cos`/`L_push`/`L_seg` + M5/M7/M22/M23）全部通过 `proto_distance_scores`，
而它就是 `1 − max cos`。metric head `W` 和原型都是朝"最近邻"最优化的。
推理时单方面换算子 = 训练/推理不一致；要真正做成，必须**同步改训练损失**——
而这正是 M22/M23/M36 那一类"损失侧改动"的范畴，历史上除 M22 外全负。

## 4. ③ bank 分支最值得做

支持它的三点：

1. **库最密**：90112 patch/stage，是 ② 的 22 倍（88 张增强图 vs 4 张原图），
   `d̄` 的统计最稳，全局项权重 0.35~0.50，是真正的"综合多原型"。
2. **免训练**：bank 本来就不训练，不存在 ① 那种训练/推理不一致。
3. **改动极小**：`util/memorybank.py` 里 `faiss_index.search(q, k=1)` 是硬编码的 1-NN；
   改成 `k=K`（K≈512）就能同时拿到 `d_min` 与 `d̄`。
   **额外的 mean 是零成本**（特征提取才是耗时项），所以同一遍推理能免费产出 min 与 geom 两个版本。

风险与注意事项：

* bank 是 VisA **最强单支**（78.74），且在融合里占 **0.7 权重**；若 geom 让它的图像级下降，
  会直接拖累融合（MVTec 上 geom 就出现过"图像级 −0.35、像素级 +0.55"的交换）。
  ⇒ 必须同时保存 `min` 版做对照，任何结论都要看三支与融合四组数字。
* bank 的图是**两个 stage 的 1-NN 距离平均**得到的，geom 有两种接法，都要试：
  (a) 每个 stage 各自 geom 后再平均；(b) 先分别平均两 stage 的 `d_min` 与 `d̄` 再做 geom。
* `d̄` 用 `k=512` 的前 512 近邻均值近似全库均值（90112 个 patch）；可对比 k=1024 验证近似误差。

## 5. 一个可用的"先验预测器"

② 上，log 变异比与该类的 geom 增益明显相关：

| 类别 | ② 的 log 变异比 | geom 裸分支增益 |
|---|---|---|
| candle | 0.134 | **+0.01**（几乎无变化） |
| macaroni2 | 0.375 | **+3.74** |

⇒ 变异比小 ⇒ geom ≈ min ⇒ 白改；变异比大 ⇒ 全局项带来真实信息。
这个量只要一次推理（几十秒/类）就能测，**可以在跑完整实验前先筛一遍哪些类/哪些数据集值得改**。

## 6. 建议的实验方案与成本

一次三合一的推理，每个测试图同时输出六张未平滑图：
① min / geom、② min / geom、③ bank min / geom，然后枚举融合组合。

| 步骤 | 成本 |
|---|---|
| ① ②（复用现有 forward） | VisA 12 类 / 2 卡 ≈ 10 min |
| ③ bank 重推（12 类，含建库） | 12 类 / 2 卡 ≈ 70 min |
| 融合枚举 + 汇总 | ≈ 10 min |

**推荐顺序**：③（预期最高、无训练/推理不一致）→ 若有效再考虑训练侧对齐让 ① 也能用。

### 结论（与 §1 的预测对照）

1. **`learn_geom` 确实退化了**：裸分支只有 **+0.38**（≈ 无变化），融合 **−1.07**。
   §1 预测"d̄ 在 64 个可学习原型上近似常数（变异比 0.008~0.012）→ geom 只是 min 的单调变换"，
   实测一致。融合列更差，是因为该图量级是基线的 ~13 倍，对齐后仍引入噪声。
2. **但公式本身没问题——问题在参考集**：把全局参照换成**映射到同一度量空间的 4096 个真实正常 patch**
   （`learn_geom_bank`），裸分支从 69.38 → **74.13（+4.75）**，几乎追平原始库侧的裸分支水平
   （`raw_geom_rawonly` = 76.31）。说明可学习侧不是"不能用 geom"，而是"只有 64 个原型、太稀疏，d̄ 无信息"。
3. **`raw_geom` 仍是三处里单项收益最大的**（融合 +2.78）。但它与 `learn_geom_bank` 作用在不同分支上，
   两者有互补可能（macaroni2：raw +4.84、bank-全局 +5.65；pcb3：+6.75 / +2.63），值得做一次组合测试。
4. 副作用提醒：`learn_geom_bank` 需要把 4-shot 的原始库过一遍 `token_mapping`（4096×768），
   显存与耗时约为原始库侧 geom 的 1 倍，可接受。
